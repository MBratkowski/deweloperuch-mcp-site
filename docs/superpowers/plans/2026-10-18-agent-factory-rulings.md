# Agent factory: controller rulings

Decisions taken during the subagent-driven execution of `2026-10-18-agent-factory.md`, in the order they were made. Each states what was decided, why, and what it costs if wrong. Rulings amend the plan; the spec was aligned afterwards (commit 735aa84).

- Ruling R1: Task 5 may add its in-page scripts (clipped text, overlaps) to tools/factory/detectors.py — the plan puts all in-page JavaScript there (Task 3) and Tasks 6–8 extend it the same way — cost if wrong: none beyond a file listed late.
- Ruling R2: The engine-diff calibration (Task 8 step 3) moves to Task 9, which creates the probe CLI and the `--report-deltas` flag; Task 8 ships with engine_diff_px = 8 from config — a step cannot use a CLI that does not exist yet — cost if wrong: a threshold change one task later.
- Ruling R3: Task 10 adds the CLI `python -m tools.factory.ci_facts --out DIR`, writing DIR/findings.json as `{"target": "ci", "groups": [...]}` (the probe's shape), so the QA workflow can run it and triage reads it like probe output — Task 16 needs a command and none is defined — cost if wrong: a renamed flag in one workflow step.
- Ruling R4: Task 15 may add a helper listing Check/Pages runs since a SHA and reuse ci_facts.failed_tests — flaky verification needs history since the merge, which find_flakes does not give — cost if wrong: a small helper in the wrong module.
- Ruling R5: Task 16 steps 6–7 and Task 22 step 5 are owner steps (phase 0 and post-merge acceptance); implementers stop before them and the final message lists them — they need the GitHub App, secrets and a merged branch — cost if wrong: none; nothing can run them earlier.
- Ruling R6: normalize_selector strips only nth-child/nth-of-type, not "generated ids" (spec) — the site is static and every id comes from the templates; no id generator exists — cost if wrong: a future dynamic id would split one defect into duplicate issues until normalisation is extended.
- Ruling R7: open_cell takes `browser: Browser` (engine must match cell.engine) instead of `playwright: Playwright`; PageRun gets close() for its context — Task 9 requires one browser per engine per run, which a per-call launch from Playwright cannot give — cost if wrong: one signature change in Tasks 9/13/15/19/20 callers, all of which launch browsers per engine anyway.
- Ruling R8: open_cell reads mode options from load_config().matrix.modes (cached); "height" is ignored there because Cell.height already carries it; menu mode raises ProbeError when the toggle is missing — modes are config (global constraint), and a missing toggle at mobile widths means the probe cannot measure what it claims — cost if wrong: a red QA job instead of a filed issue when the menu markup changes.
- Ruling R9: open_cell raises ProbeError when a same-host stylesheet, script or font response has status >= 400 or fails (not aborted by the guard); RequestLog records same-host bad statuses for every resource type (images included, which the images check reports as defects) — Review Focus 1 says a half-loaded site stops the probe; images are content defects, not infrastructure — cost if wrong: a genuinely broken CSS link shows as a red QA job instead of a filed issue.
- Ruling R10: SCROLL_UNREACHABLE measures real sequential navigation per engine (a temporary focusable sentinel before each candidate scroller, Tab, check document.activeElement); the canary is asserted per engine with a new pytest marker `multi_engine` (added here, skipped when the engine binary is missing; Task 8 wires it into CI) — the rawest evidence is the engine's own Tab behaviour, which is what #46 measured — cost if wrong: WebKit Tab quirks (Option-Tab) could hide a real defect in WebKit cells.
- Ruling R11: `console` ignores "Failed to load resource" messages for URLs the request guard aborted itself (those are `network` findings); `network` reports blocked third-party hosts plus failed/bad-status same-host resources except images (those are `images` findings) — one defect, one check, so one issue — cost if wrong: a console error that coincides with an aborted URL could be hidden.
- Ruling R12 (refines R11): `console` drops every console error whose text starts with "Failed to load resource" (all engines), because `network` and `images` own every resource-load failure via RequestLog; the location.url filter goes away — engine-independent and one defect stays one check — cost if wrong: a resource failure the RequestLog misses would go unreported (none known: route + response + requestfailed cover them).
- Ruling R13: Task 9 calibrates engine_diff_px with Chromium vs WebKit only and adds an `--engines` CLI filter; Firefox deltas are checked on the first CI/QA dry run — Firefox cannot launch in this sandbox — cost if wrong: Firefox-specific noise above the threshold appears first in the dry run (acceptance step 1), where the owner reviews false alarms.
- Ruling R14: reproduce() returns 1 when any new finding in the group's cells has the same (check, page, mode, normalised selector) as the group (engine-diff re-runs the Chromium reference cells too); CI groups (flaky, deploy-stale) are not browser-reproducible → ValueError — a partially fixed defect must still count as reproducing, which an exact fingerprint (bands, engines) would miss — cost if wrong: a different defect on the same selector keeps an issue open.
- Ruling R15: render_reference takes `allowed_hosts` (default {"fonts.googleapis.com", "fonts.gstatic.com"}); its test passes local hosts only and asserts example.com is aborted, plus asserts the default set — tests must stay offline and the plan's test would have fetched Google Fonts — cost if wrong: none.
- Ruling R16: checks per mode — default, no-js, reduced-motion, short: all CHECKS; menu: all except overlap (the open menu covers content by design); keyboard: focus only; engine-diff from default-mode cells only — cost if wrong: an overlap defect inside the open menu goes unreported.
- Ruling R17 (amends plan Task 8 rule): compare y only for `header` elements and elements inside a `header` (the top bar); everything else compares x and width only. engine_diff_px stays 8 as a floor until Firefox is calibrated on the first CI/QA dry run — absolute y of lower landmarks accumulates every height difference above them (spec: geometry must keep font noise out); 8 because Firefox is uncalibrated — cost if wrong: engine shifts of 3–8 px and vertical shifts below the header go unreported.
- Ruling R18: issue body headings are exactly "Problem", "Where", "Reproduce", "Actual and expected", "Why it matters", "Evidence", "Acceptance criteria", "Likely sources" (the spec's eight items; item 4 is one section); script reproductions add a `<!-- factory:script=<evidence url> -->` marker read by `script_in(body)` — verify and review need the script, and the groups marker is empty for script drafts — cost if wrong: one extra marker to parse.
- Ruling R19: load_drafts validates in Python (no jsonschema dependency; global constraint allows only actionlint-py) and a test asserts .github/factory/schemas/drafts.json and the validator agree on required fields and enums — the schema feeds claude-code-action --json-schema, the validator guards filing — cost if wrong: drift caught by that test only for required fields/enums.
- Ruling R20: detector drafts render Reproduce as the probe --reproduce command plus the group JSON in a <details> block named group.json (passed as render_issue's script_source); the command targets the live URL — makes the one-command reproduction actually runnable from the issue — cost if wrong: a long JSON block in each issue.
- Ruling R21: check_drafts verifies CI groups (flaky, deploy-stale) by their presence in the same run's ci_facts output (probe-out/ci/findings.json fingerprints), not by a browser reproduction (reproduce raises ValueError for them) — they are not browser-reproducible and were just computed from CI — cost if wrong: none beyond trusting a minutes-old CI read.
- Ruling R22: agent repro script contract — print exactly one stdout line `REPRODUCED: <measurement>` and exit 1 when present; `NOT REPRODUCED` and exit 0 when absent; any other outcome (other code, missing line, traceback, timeout) = 2 (reproduction error). check_drafts enforces it; the QA prompt (Task 16) states it — a Python crash also exits 1, so the exit code alone cannot mean "found" — cost if wrong: an agent script that forgets the line is dropped instead of filed.
- Ruling R23: `probe --reproduce` accepts a single group object or a JSON array; for an array it exits 1 when ANY group reproduces (the defect is still there), 0 when none, 2 on error; check() keeps its "all groups reproduce" filing gate — the issue command must run for multi-group drafts, and "still present" means any part remains — cost if wrong: a partly fixed multi-group issue keeps showing as reproducing.
- Ruling R24: CI-only drafts (flaky, deploy-stale) render Reproduce as `uv run python -m tools.factory.ci_facts --out ci-out` followed by `grep <fingerprint> ci-out/findings.json`, plus the run links from the group note — the probe refuses CI groups by design — cost if wrong: none.
- Ruling R25: the status issue is found by a `<!-- factory:status -->` marker in a body authored by a trusted login (not by title, which any writer can edit); shadow verdicts are read from the latest trusted comment carrying `<!-- factory:verdict=… sha=… -->` on each closed factory PR; agreement() takes normalised dicts {number, merged, verdict} — cost if wrong: none.
- Ruling R26 (corrects plan Task 15): is_deployed is true when GET /compare/{merge_sha}...{deployed} has status "identical" or "ahead" (deployed contains the merge); the plan's "behind" is the inverse — GitHub's compare status describes head relative to base — cost if wrong: none (tests pin both directions).
- Ruling R27: the spec's "new S1 or S2 finding on a page the merge changed" triggers a regression only when that group (a) has dedup decision "new", (b) is on a page in pages_changed(merge files), (c) reproduces on the live site and (d) does NOT reproduce on a local build of the merge's parent commit (git worktree + local_site) — measured in the no-secret verify job — so a pre-existing defect discovered after a merge never reverts a good fix — cost if wrong: a merge-caused regression on an unchanged page goes unreverted (still filed as a normal issue).
- Ruling R27b (amends R27): a merged issue regresses through a probe group only when the group (a) has dedup decision "new" or "regression", (b) is on a page in pages_changed(merge files), (c) is S1/S2, (d) reproduces on live, (e) does NOT reproduce on a local build of merge_sha^, and (f) DOES reproduce on a local build of merge_sha; builds cached per revision; a 2 at any build → error — present exactly at the merge and absent just before it is attribution to that merge alone; live-only differences and later merges no longer revert a good fix; a re-broken old defect now counts — cost if wrong: a regression visible only on the live site is filed as an ordinary issue instead of reverting.
- Ruling R28 (amends plan Task 16 job graph): the probe job runs the full matrix on the live site only (+ reference + ci_facts); confirmation on main happens per draft in check_drafts — a second full matrix on main would double the run for no decision — cost if wrong: none (check_drafts already gates on main).
- Ruling R29: job order guard → probe → {verify → verify-act, triage} → file (needs triage AND verify, so verify check reads issues before this run files) → dispatch-status (needs file, verify-act); with dry_run, verify-act and dispatch-status are skipped and file runs --dry-run — dry run means no GitHub writes at all — cost if wrong: none.

- Ruling R31 (corrects my R22 dispatch wording): script (AI-review) drafts get a deterministic fingerprint from `fingerprint("ai-review", page, "default", selector, (), ())`, exposed as `uv run python -m tools.factory.findings fingerprint --check ai-review --page P --selector S`; qa.md tells the agent to use it and allowedTools includes that command — the spec files proven AI-review findings as factory:found, which needs a stable fingerprint across nights; my "fingerprints only from findings.json" made them suggestions-only — cost if wrong: two runs describing the same defect with different selectors file twice.

- Ruling R38: two layers. (a) Static fence (Task 17): new and existing test modules may only add, at top level, imports, `def` (tests or helpers), `class`, and assignments of literal constants to new names; anything else at top level (calls, pytest_plugins, attribute or subscript assignment, del, hooks named pytest_*, if/try/with/for blocks) → hard; a new def/class/assignment must not rebind a name imported or defined in the base module or a fixture name defined in any conftest.py (read via ast) → hard; `del` of or assignment to a base test name → hard; a `raise` added inside a base test → hard; regex also covers `SkipTest` and `skip.Exception`; _skeleton descends into all compound statement bodies; HTML copy guard also compares regex counts of `<script\b`, `</script\b`, `<style\b`, `</style\b`, `<textarea\b`, `<!--`, `-->`, `--!>`, `<![CDATA[` on the raw files and adds `value` and meta[name^=twitter:] content to the text attributes. (b) Behavioural backstop (Task 20 evidence job, decisive): run the chromium suite and the visual job's tests on base and head with --junitxml; every test id that passed on base must be collected and pass on head, else the evidence is not green (the reviewer cannot approve, the merger cannot merge) — static analysis of Python cannot be complete; the rawest evidence is what pytest actually ran — cost if wrong: the evidence job takes two full test runs.
- Ruling R39 (bounds the static arms race): (1) definition-time code and unusual test structure become SOFT review reasons ("test code needs a human: <path>: <what>"): decorators/defaults/annotations/class bases containing any Call other than pytest.mark.*/pytest.fixture/pytest.param with Call-free arguments; class-body statements other than def, literal assignment, docstring, pass; setup_/teardown_ module/function/class functions and setUpModule/tearDownModule; new autouse fixtures in existing modules; non-literal getattr; attribute/subscript assignment inside test bodies; a raise added in a helper (a raise added in a BASE TEST stays hard, a return added anywhere stays hard); (2) rebind checks count bindings per name (hard only when head binds a name more often than base, or a changed import changes its from-module); in-place edits fall to R37 "existing tests changed" (soft); (3) HTML: parser-divergent forms are copy changes — regex `</(script|style)\b(?!\s*>)`, `<!---?>`, `--!>`, `--\s+!?>` present in head but not base; (4) R38(b) is refined for Task 20: the evidence job runs the BASE commit's tests/ tree in its own pytest session against the HEAD site build, and head-added tests in a separate session — head test code then cannot rewire base tests; that is the decisive control — the realistic risk is a lazy fixer weakening tests, which R37 hard/soft rules catch; deliberate sabotage needs a human (soft) and is defeated by session isolation — cost if wrong: more PRs land in needs-human.
